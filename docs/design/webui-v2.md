# WebUI v2 設計

## この文書の位置付け

WebUIを機能を絞って作り直すための設計を定める。2026-10-08に対話で1項目ずつ確定した内容を、実装Issueの起票元としてまとめる。

[webui-use-cases.md](./webui-use-cases.md) の「使用者と前提」は引き継ぐ。一方、同文書の2つの利用モード (ラボ/作品制作) とPreset昇格は廃止し、本文書の7つのユースケースに置き換える。

旧UI (`apps/web`) にはrouterが無く、`App.tsx` は2308行で `useState` を59個持つ。`apps/web/src` 全体は約38.5k行ある。機能を足し続けた結果、どこから何をすればよいかが分かりにくくなった。v2では、使う機能だけを最小限で作り直す。

## 使用者と前提

[webui-use-cases.md](./webui-use-cases.md) の「使用者と前提」のとおりとする。要点は次のとおり。

- 使用者は1人だけである
- 生成はRemote GPUで直列に実行するため、待ち時間が必ず発生する
- 試行回数が多く、生成物が溜まる
- うまくいった設定を繰り返し使う

ただし、素材の正本についての前提は変える。キャラクターとシーンの正本はMyComfyUIに置く。`novel-writer` からは取り込むだけにする (P2)。これは [PLAN.md](../PLAN.md) の「`novel-writer`の作品正本は参照専用」という方針の転換である。

## 7つのユースケース

上位ナビは次の7つのユースケース (UC) で構成する。

1. Project管理: キャラクター (衣装ごとの画像、固定タグ、性格など) とシーン (背景、登場キャラ、服装、時間帯、ポーズ・表情) を管理し、生成した画像・動画・音声・BGMを紐づける
2. 画像生成: プロンプトで新規に生成し、参照画像を使って生成・修正する。Projectのタグを補完でき、衣装を選んで生成できる。日本語からプロンプトへ変換できる。背景、キャラ、複数人を扱う。Project無しでも試せる
3. 動画生成: プロンプトだけで、または画像・音声を参照して生成する。Projectから補完でき、日本語から変換できる
4. 音声生成: 台詞から生成する。Cloneの声はProjectから補完する。日本語から変換できる
5. BGM生成: プロンプトから生成する。日本語から変換できる
6. シーン生成: キャラ画像 (登録済みならスキップ) → シーン画像 → 音声 → BGM → 動画 → 統合 の順に進める。各工程でUC2〜5の機能を使う
7. Viewer (資産管理): 生成物を画像・動画・音声・BGMのタブに分け、フィルタで探す

## 技術構成と移行

- frontendは `apps/web-next` に新しく作る。backend (`apps/api`) は既存のAPIを流用し、足りない分だけ足す
- 使うライブラリは React Router、TanStack Query、Mantine。状態管理ライブラリは入れない
  - 画面の対象 (Project、Sceneなど) はURLのクエリに持たせる
  - サーバーの状態はTanStack Queryで扱う。WebSocket (`/events`、`apps/api/src/mycomfyui_api/events.py:198`) のイベントを受けたら、該当するQueryのキャッシュを無効化する
  - 各ライブラリのバージョンとReact 19への対応は、実装前に公式資料で確認する
- `apps/web-next` で全画面を置き換えたら、旧 `apps/web` を削除する (#612で削除済み)

## 共通のレイアウト

### 上位ナビ

- MantineのAppShellで、左に縦のナビを置く。アイコンとラベルを並べ、アイコンだけの幅に畳める
- ナビの項目は Project / 画像 / 動画 / 音声 / BGM / Viewer の6つとする
  - シーン生成はSceneを1つ決めないと開けないため、ナビに置かない。Project画面のシーンタブの「シーン生成へ」から開く
- ナビのリンクは、今のURLにある `project` を引き継ぐ。Projectを選んだまま画面を移っても対象が外れない。状態はURLにだけ持たせ、全体の状態としては持たない
- `/` を開いたら `/projects` へ移す

### ヘッダー

- Jobの件数 (例: 「実行中1・待機3」)。クリックでJobのドロワーを開く
- 現在のProject名。クリックでProject画面へ移る
- 設定ボタン。Qwenの接続先のダイアログを開く

### Jobの進行表示

- ドロワーには、待機中・実行中・直近に終わったJob (失敗を含む) を新しい順に並べる
- 1行には、種別、Project/Scene、状態、経過時間を出す。実行中ならプレビューのサムネイル (`GET /generation-jobs/{id}/preview`、`routers.py:1824`) も出す
- 操作は次の3つとする
  - 中止 (待機中・実行中。`POST /generation-jobs/{id}/cancel`、`routers.py:1857`)
  - 再実行 (失敗。`/replay`、`routers.py:4008`)
  - 結果を開く (Viewerで該当の1件を開く)
- 失敗した行には `failure_message` を出す
- 完了と失敗はトーストで知らせる。トーストから結果を開ける
- 投入したJobはサーバーのキューで進むため、待っている間に別の画面へ移ってよい。件数、ドロワー、各画面の結果欄はWebSocketのイベントで更新する
- `/jobs` のような独立した画面は作らない

Jobの状態は `queued` / `running` / `cancelling` / `succeeded` / `failed` / `cancelled` の6つである (`schemas.py:56-58`)。進捗率の欄は無いため、進捗率は表示しない。

### Qwen設定

- ヘッダーの設定ボタンから小さなダイアログで開く
- 項目は `base_url` / `model` / `status_url` の3つとする。画像添付を外したため、`supports_images` は出さない
- 保存は既存の `GET` / `PUT /qwen` (`app_settings.py:128,134`) を使う。接続先をローカルのOllamaとg18で切り替える運用があるため、APIを再起動せずに変えられるようにしておく

## UC1 Project管理

### Project

- 項目: 名前、説明、作成日時、更新日時
- 一覧は更新日時の降順に並べる
- 削除するとゴミ箱へ移る。ゴミ箱から復元でき、完全削除もできる。ゴミ箱のProjectは一覧から隠す
- 完全削除で消すのは、Project・キャラクター・シーンの定義だけとする。生成物は「Project無し」としてViewerに残り、要らないものはViewerで個別に消す
- 持たないもの: アーカイブ、進捗、生成の既定値、export/import、テンプレート

### キャラクター

- 項目
  - 名前
  - 固定タグ: どの衣装でも常にプロンプトへ入るタグ (髪型、髪色、目の色、体格など)
  - ネガティブタグ
  - 性格・設定: 日本語の自由記述。プロンプトへの変換と、音声のcaptionの変換で文脈として使う
  - 代表画像
  - 声の参照: Clone用の参照音声と、その書き起こし
  - 衣装の一覧
- タグの自動抽出: 既存のWD14 tagger (`POST /image-tags`、`routers.py:4397`) を流用する
  - ボタンで手動で実行し、結果をチェックボックス付きの一覧で出す。チェックしたタグだけを追加する
  - 追加先は実行した画面に合わせる。キャラクター画面なら固定タグ、衣装画面なら衣装タグへ入る

### 衣装

- 項目
  - 名前 (例: 制服、私服(夏)、パジャマ)
  - 衣装タグ
  - ネガティブタグ
  - 説明: 日本語の自由記述
  - 参照画像: 複数枚。並び順の先頭を代表とする
- タグの自動抽出はキャラクターと同じ仕組みで持つ
- 生成時のプロンプトは「キャラの固定タグ+衣装タグ」、ネガティブは「キャラ+衣装」を合成する
- 持たないもの: 参照画像の役割ラベル (正面/横/背面/顔アップ)、参照画像セットの一括生成

### シーン

- 項目
  - 名前、並び順
  - 親Scene ID: 欄だけ用意して空のままにする。Shotは作らず、Sceneの1階層とする
  - 概要: 日本語の自由記述
  - 背景: 日本語+タグ
  - 時間帯: 朝/昼/夕方/夜から選ぶ。選んだ値に応じて `morning` / `day` / `sunset` / `night` のタグを自動で付ける
  - 登場キャラ (複数): キャラ、衣装 (そのキャラの衣装から選ぶ)、ポーズ (日本語+タグ)、表情 (日本語+タグ)
  - 台詞の一覧: 話者 (キャラ)、台詞文、演技指示
  - BGMの雰囲気: 日本語
  - 動画の動き: 日本語
- 「日本語+タグ」の欄は、日本語を書いてボタンを押すとタグへ変換する。変換結果は手で直せる

### 生成物との紐づけと採用

- 生成物は Project、Scene、キャラ、衣装をそれぞれ任意で持つ
- 生成画面で対象を指定して生成すれば、その値で自動的に紐づく。Viewerから後で付け替え・解除できる
- 衣装の参照画像は、生成物の「この衣装の参照に追加」か、手元の画像のアップロードで登録する
- 画像ごとのメモは生成物そのものに付ける。衣装の画面とViewerのどちらからでも同じメモを見て編集できる
- 採用: シーン×種別 (シーン画像、台詞ごとの音声、BGM、動画、統合) ごとに1件を指定できる。シーン生成 (UC6) は、採用済みのものを次の工程の入力に使う
- 不採用の印も付ける。Viewerで不採用だけを絞り込み、まとめて消せる

### 画面

- `/projects`: Projectの一覧 (カード表示)。ゴミ箱への切替タブを持つ
- `/projects/:id`: Projectの詳細。タブは「キャラクター」と「シーン」の2つ
  - キャラクタータブ: 左にキャラクターの一覧、右に選んだキャラクターの編集欄。衣装は編集欄の中にカードで並べ、クリックで衣装の編集ドロワーを開く
  - シーンタブ: 左にシーンの一覧 (ドラッグで並べ替え)、右にシーンの編集欄。採用済みの生成物をサムネイルで並べ、「シーン生成へ」(UC6) と「Viewerで候補を見る」(UC7、このシーンで絞り込んだ状態) へ移れる
- 編集は保存ボタンで確定する。未保存のまま画面を離れるときは確認を出す

## UC2 画像生成

### 入力

- 対象 (すべて任意): Project → Scene → 登場キャラ (複数可。キャラと衣装の組)
  - キャラの固定タグ・衣装タグ・ネガティブを合成して「補完タグ」にする
  - Sceneを選ぶと、背景・時間帯・ポーズ・表情も補完タグに入る
- 生成方法のタブ
  - 新規: `anima_txt2img`
  - 参照: 「変えたい要素」のチェック (ポーズ・表情を変える / 衣装を変える) から、テンプレートと強度を自動で決める。旧UIのロジックを流用する (`apps/web-next/src/imageGen/deriveForm.ts` へ移植済み)。ポーズ・表情だけなら `anima_ref_siglip` (強度0.5)、衣装だけなら `anima_ref_incontext` (強度1.0) となる。強度は「詳細」で手で直せる
  - 修正: 「全体を変える」(`anima_img2img`、denoiseのスライダー) / 「一部を描き直す」(`anima_inpaint`) / 「拡大」(`image_upscale`)
  - 参照と修正では、元画像を1枚選ぶ。出どころは、生成物、衣装の参照画像、アップロードのいずれかとする
- 常に出すパラメータ: サイズ (縦横比のプリセットと縦横の入れ替え)、枚数、seed (ランダム/固定)
- 「詳細」に折りたたむもの: モデル (unet/clip/vae)、steps、cfg、sampler/scheduler、hires、denoise/参照強度、スイープ
- 作らないもの: `sd15_controlnet`、Preset/LookProfile、派生、投入前の確認 (preview)

### inpaintのマスク

- 元画像の上にcanvasを重ね、ブラシで塗ってマスクを作る。ブラシの太さ、消しゴム、全消去を持つ
- マスク画像のアップロードも受け付ける

旧UIはマスクを描く機能を持たず、登録済みの画像をマスクとして選ぶだけだった (旧 `apps/web/src/components/ImageDerivationPanel.tsx:297-302`、#612で削除)。

### 複数人

- プロンプトの合成だけで対応する。新しいワークフローは作らない
  - 登場キャラの数から人数タグ (`2girls`、`1boy 1girl` など) を自動で付ける
  - キャラごとに「固定タグ+衣装タグ+ポーズ+表情」をまとめ、キャラ単位の区切りで連結する
  - ネガティブは全員分の和集合にする
- 参照と修正は1人ずつに限る
- 髪色や衣装が別のキャラに混ざることがある。混ざったら修正タブのinpaintで直す
- regional promptは作らない

### プロンプト

- プロンプト欄は2層に分ける
  - 補完タグ: Projectから自動で合成する。読み取り専用で、外したいタグだけを×で外せる
  - 自由欄: 手書きか、変換の結果を入れる
- 生成時は「補完タグ+自由欄」を、重複を除いて連結する
- 日本語欄に書いて「変換」を押すと、自由欄だけが置き換わる。補完タグはLLMに文脈として渡し、重複するタグを出させない
- 「直す」ボタンで、自由欄を土台に日本語で指示した点だけを直す (現行のレビュー機能)
- 変換と「直す」の結果は差分で表示し、「適用」か「破棄」を選ぶ
- 作らないもの: タグの確信度のしきい値スライダー、画像の添付 (既定のQwenは画像を受け付けない。`settings.py:90`)

### スイープ

- 「詳細」に「スイープ」スイッチを置く。オンにすると軸の入力欄と組み合わせ方が出る
  - 軸は seed / cfg / steps / プロンプト断片の4つ。値はカンマ区切りで入れる
  - 組み合わせ方は全組合せ (cartesian) か対 (zip)
- 投入前に件数を出す (例: cfg 3値 × steps 2値 = 6件)
- 結果は軸のラベル付きのグリッドで出す。各セルで、採用/不採用、衣装の参照に追加、Viewerで開く ができる
- 実験名は自動で付ける
- A/B比較の画面は作らない。グリッドで代わりにする
- Project無しでもスイープできるようにする

### 画面

- URLは `/image?project=&scene=&character=&outfit=`。シーン生成やProject画面からはこの形で開く
- 左が入力欄、右が結果欄
- 結果欄には、この画面から投入した生成を新しい順に出す。待機中・実行中はプレースホルダで出し、完成したら差し替える
- 結果のカードの操作: 拡大表示、メモ、採用/不採用 (Sceneの指定がある場合)、衣装の参照に追加、この設定を入力欄へ戻す、修正タブへ送る、Viewerで開く
- 修正・参照の結果は、元画像のProject/Scene/キャラ/衣装の紐づけを引き継ぐ
- 入力欄の内容は、最後に使った値をブラウザに保存し、画面を離れても残す。「リセット」で初期値へ戻す
- 投入はキューに積むだけなので、投入した後すぐに次を入力できる

## UC3 動画生成

- URLは `/video?project=&scene=&character=&outfit=`。画面の形とプロンプトの2層はUC2と同じとする。日本語からの変換は `POST /video-prompt-assists` (`routers.py:5446`) を使う
- 方式のタブ
  - 画像から: `minimax_h3_i2v`。先頭フレームの画像1枚
  - 参照から: `minimax_h3_ref2v`。参照画像1〜9枚
  - プロンプトだけ: 「画像生成 → i2v」の2段を自動で実行する。中間の画像も生成物として残す
- Projectからの補完
  - キャラと衣装を選ぶと、衣装の参照画像を参照の枠へ入れる
  - Sceneを選ぶと、採用済みのシーン画像を先頭フレームに入れ、「動画の動き」を日本語欄に入れる
- 台詞の音声 (生成物かアップロード) を1本、`guide_audio` に渡せる
- BGMは動画生成では使わず、統合 (UC6) で重ねる
- 常に出すパラメータ: サイズ、長さ (秒で入力し、フレーム数へ変換する)、seed。モデルなどは「詳細」に入れる

## UC4 音声生成

- URLは `/voice?project=&scene=`
- TTSはIrodori-TTSだけを使う
- 生成の単位は「台詞1行 = 1 Job = 1生成物」とする。シーンの台詞ごとの採用とそのまま対応する
- 入力
  - 台詞文、読み (任意)、話者
  - 声: 「Clone」(参照音声+書き起こし) か「声質の文章」(caption、500字以内)
  - 演技指示 (日本語)
- Projectからの補完
  - 話者にキャラを選ぶと、キャラの声の参照をCloneに入れる
  - Sceneを選ぶと台詞の一覧を出し、1行ずつ、または全行をまとめて投入できる。まとめて投入しても行ごとに別のJobになる
- 日本語からの変換: 「キャラの性格・設定+演技指示」から、その行のcaptionを作る
- 常に出すパラメータ: seed、ASRによる読みの検証
- 作らないもの: `duration_sec` / `pad_to_duration` (Shotの尺に合わせる機能。Shotを廃止したため)

## UC5 BGM生成

- URLは `/bgm?project=&scene=`。テンプレートは `ace_step_bgm` だけを使う
- 日本語の雰囲気欄に書いて「変換」を押すと、タグ欄へ入る (`POST /music-prompt-assists`、`routers.py:5473`)。結果は差分を見て適用する
- Sceneを選ぶと、「BGMの雰囲気」を日本語欄へ入れる
- 歌詞の欄を出す。歌詞が空のときだけ、`instrumental` を補完タグとして自動で付ける
- 常に出すパラメータ: 長さ (秒)、seed、枚数
  - 長さの既定値は、Sceneに採用済みの動画があればその長さ、無ければ30秒とする
- 「詳細」に入れるもの: steps、cfg、sampler、scheduler、モデル
- スイープは付けない

## UC6 シーン生成

- URLは `/scenes/:id/produce`
- 左に6工程のステッパーを置く。工程は キャラ画像 → シーン画像 → 音声 → BGM → 動画 → 統合
  - 各工程に状態を出す: 未着手 / 生成中 / 候補あり / 採用済み / スキップ
  - どの工程へもクリックで移れる。音声やBGMを先に作ってもよい
- 右には各工程の画面を出す。UC2〜5の画面の部品を埋め込み、Project/Scene/キャラを指定した状態で開く。結果のカードで「採用」を押すと、その工程が採用済みになる
- 工程ごとの補完
  - キャラ画像: 登場キャラ×衣装ごとに、参照画像の有無を出す。あればスキップでき、無ければ生成して「衣装の参照に追加」する
  - シーン画像: シーンの背景・時間帯・登場キャラ・ポーズ・表情から補完タグを作る
  - 音声: 台詞の一覧を、行ごとに生成・採用する
  - 動画: 採用したシーン画像を先頭フレームに使う。採用した台詞の音声を `guide_audio` に渡すかを選べる
  - 統合: 採用した動画・台詞の音声・BGMを入れる。台詞は前から順に詰めて配置する。開始時刻と音量は手で直せる。動画の尺を超える行は投入前に警告する
- 「残りを一括実行」を持つ。まだ採用していない工程を順に実行し、各工程の最初の候補を自動で採用して統合まで流す。気に入らない候補が採用されたまま先へ進むことがあるため、後で工程を開いて採用を差し替えられるようにする
  - 進め方: frontendで進める。画面がJobの終了を待ち、次の工程のJobを投入する。画面を閉じると止まるが、投入済みのJobは取り消さない。開き直したときは採用済みの工程を飛ばし、残りの工程から続ける。実行の状態はどこにも保存せず、採用の状況から毎回求め直す
  - 実行する工程: キャラ画像 → シーン画像 → 音声 → BGM → 動画 → 統合の順に、採用もスキップもされていない工程だけを実行する。各工程の候補は、Jobの生成物のうち種別が合い、ゴミ箱に入っていない最初のもの
  - 進み具合と中止: 実行中は、ステッパーの各工程に 待機 / 実行中 / 完了 / スキップ / 失敗 を出す。「中止」を押すと実行を止め、いま待っているJobを取り消す。工程が失敗したら、そこで止めて、止まった工程と理由 (Jobの失敗メッセージ、または投入できなかった理由) を出す
  - 結果欄: 一括実行で投入したJobは各工程の結果欄にも入るので、後で工程を開いて別の候補に採用を差し替えられる
  - 工程ごとの扱い
    - キャラ画像: 参照画像が無い衣装ごとに1枚生成し、その衣装の参照に追加する。参照がそろっていればスキップする。衣装の指定も肖像も無い登場と、衣装が見つからない登場は、知らせを出して飛ばし、実行は続ける
    - シーン画像: シーン画像の画面と同じ補完タグ・既定値で1枚生成し、採用する。プロンプトが空になるなら止める
    - 音声: 台詞の1行を1つのJobとして順に投入し、行ごとに最初の候補を採用する。話者のキャラに声の参照が無い行は、知らせを出して飛ばす。全行がそうで投入できる行が1つも無いときも、飛ばした行の知らせを出して先へ進む。投入できる行がすべて採用済みなら完了とみなす。台詞が無ければスキップする
    - BGM: シーンの `bgm_mood` をBGMのタグ変換 (`/music-prompt-assists`) でタグにして生成する。長さはBGMの画面の既定値に従う。`bgm_mood` が空のとき、変換に失敗したときは止める
    - 動画: 動画の画面と同じ補完 (i2v、先頭フレームは採用したシーン画像、プロンプトはシーンの `video_motion`) で生成する。採用したシーン画像が無いとき、`video_motion` が空のときは止める
    - 統合: 台詞の音声を先頭から詰め、既定の音量で動画に載せる。BGMを採用していれば既定の音量で重ねる。音声と動画の尺はブラウザで読む。台詞の音声が動画の尺を超えるとき、尺を読めないときは止める

統合はffmpegで行い、入力は動画1本 (必須)、台詞の音声16本まで (それぞれ `start_sec` と `volume`)、BGM1本 (`volume`、既定0.33) である (`adapters/compose/plan.py:31-53`)。台詞の音声が動画の尺を超えると失敗する (`executor.py:231`) ため、投入前に警告する。

## UC7 Viewer

- URLは `/viewer?tab=&project=&scene=&character=&outfit=&decision=&unassigned=&from=&to=`。フィルタはURLに持たせる。Project画面の「Viewerで候補を見る」はこの形で開く
- タブ: 画像 / 動画 / 音声 / BGM / ゴミ箱
- フィルタ (上部のバー)
  - Project → Scene → キャラ → 衣装
  - 採否 (すべて / 採用 / 不採用 / 未判定)
  - 紐づけ無し
  - 期間
- 一覧
  - 画像と動画はサムネイルのグリッドで出す
  - 音声とBGMは行のリストで出し、その場で再生する。波形は出さない
  - 新しい順に並べ、スクロールで続きを読み込む
- 詳細 (右のドロワー)
  - プレビュー、メモの編集
  - 紐づけの付け替え・解除
  - 採用/不採用
  - 生成設定 (プロンプト、seedなど)
  - 「この設定で生成画面へ」: 種別に合う `/image` / `/video` / `/voice` / `/bgm` を、入力を戻した状態で開く
  - 削除
- 複数選択の一括操作: 紐づけ、ゴミ箱へ移す
- 「不採用をまとめてゴミ箱へ」: 今のフィルタに合う不採用だけを対象にする
- 削除はゴミ箱を経由する。ゴミ箱タブで復元と完全削除ができる。完全削除の前に、件数と空く容量を出す

ゴミ箱と完全削除は既存の仕組みを流用する。生成物は `deleted_at` でゴミ箱を表し、一括操作 (`trash` / `restore` など、200件まで。`schemas.py:1884-1904`) と、完全削除の影響確認・実行 (`/artifacts/purge-preview`、`/artifacts/purge`。`routers.py:2516,2537`) がある。

## 作らない機能

次の旧UIの機能はv2で作らない。

- 2つの利用モード (ラボ/作品制作) とPreset昇格
- 派生 (修正タブと参照タブで代わりにする)
- A/B比較 (スイープのグリッドで代わりにする)
- LookProfile
- AgentPanel
- Workflow登録
- JobQueue (ヘッダーのJobドロワーで代わりにする)
- 外部画像の取込 (画像のメタデータからRecipeの下書きを作る機能。ただの画像のアップロードは、衣装の参照と修正の元画像で受け付ける)
- export/importとテンプレート
- 整合性チェック
- `sd15_controlnet`

対応するbackendのAPI (`/agent-proposals`、`/look-profiles`、`/workflows`、`/workflow-versions`、`/approval-logs`、`/external-images` など) は、置き換えの作業では消さない。旧 `apps/web` を消した後 (P3) に、生成の内部から使われていないかを調べてから消す。Recipeが `/workflows` の登録に依存している可能性があるためである。

## backendで必要な追加・変更

v2の画面に対して、現行のAPIで足りない点を挙げる。実装Issueで詳細を詰める。

- キャラクターと衣装
  - 現行のキャラクターは、Projectの設定の `characters` (`ProjectCharacterProfile`) として持っている (`projects.py:718-736`)。衣装、キャラと衣装それぞれのネガティブタグ、声の参照を持たせる
- シーン
  - 現行は `ProjectScene` と `ProjectShot` (`models.py:109,136`) を持つ。v2ではShotを使わず、シーンに背景、時間帯、登場キャラ、台詞の一覧、BGMの雰囲気、動画の動き、親Scene IDを持たせる
- Projectのゴミ箱
  - `ProjectLifecycle` は既に `trashed` を持つ (`schemas.py:36`)。完全削除で定義だけを消し、生成物の紐づけを外す
- 生成物
  - キャラと衣装への紐づけを足す。現行の生成物はProject/Scene/Shotにしか紐づかない (`models.py:509-517`)。Job作成の入力にも `character_id` が無い (`schemas.py:1313-1382`)
  - メモの欄を足す。現行の生成物にメモは無い (`models.py:496-521`)
  - 採用を「シーン×種別ごとに1件」で持つ。現行の採否は生成物ごとの3値 (`undecided` / `accepted` / `rejected`) で (`schemas.py:34`)、シーン×種別の単位を持たない。不採用の印には現行の `rejected` を使える
- 一覧 (`GET /media-items`、`routers.py:2967-2982`)
  - 衣装、採否、期間で絞り込めるようにする
  - 音声とBGMを分ける。現行の種別は `image` / `video` / `audio` / `workflow` / `log` で (`schemas.py:32`)、音声とBGMはどちらも `audio` になる。JobのRecipeから種別を出す
- スイープ
  - `scene_id` と `shot_id` の必須を外す (`schemas.py:1489-1490`)
- 動画
  - 「プロンプトだけ」のために、画像生成 → i2v の2段を自動で実行する
- 音声
  - 台詞1行を1つのJobで生成する。行ごとに演技指示を受け付ける。現行の行は `text` / `voice_id` / `reading` / `speaker` / `start_sec` だけを持つ (`adapters/voice/plan.py:225-260`)
  - 「キャラの性格・設定+演技指示」からcaptionを作る変換APIを新しく作る。現行の変換APIは画像・動画・BGMの3つだけである (`routers.py:5299,5446,5473`)
